## [0.4.0] - 2026-09-21

### ✨ Added

#### BFF

- Added initial Node.js and Express BFF.
- Added layered backend architecture using Routes, Controllers, Services, and Repositories.
- Added JSON request body handling with Express.
- Added CORS configuration for communication between the React frontend and BFF.

#### SQLite persistence

- Added SQLite as the persistent data source for clients and pets.
- Added database initialization using Node.js `node:sqlite`.
- Added `clients` and `pets` relational tables.
- Added foreign key relationship between pets and clients.
- Enabled SQLite foreign key constraints.
- Migrated client repository operations from mock data to SQLite.
- Migrated pet repository operations from mock data to SQLite.
- Added persistent client and pet identifiers generated by SQLite.

#### Clients API

- Added `GET /clients`.
- Added `GET /clients/:id`.
- Added `POST /clients`.
- Added `PATCH /clients/:id`.
- Added `POST /clients/:clientId/pets`.
- Added `404` responses for non-existing clients.
- Added nested pet data to client responses.

#### Pets API

- Added `GET /pets/:petId`.
- Added `PATCH /pets/:petId`.
- Added `404` responses for non-existing pets.

#### Frontend API integration

- Added frontend service layer for client and pet HTTP operations.
- Connected client loading to `GET /clients`.
- Connected client creation to `POST /clients`.
- Connected client editing to `PATCH /clients/:id`.
- Connected pet creation to `POST /clients/:clientId/pets`.
- Connected pet editing to `PATCH /pets/:petId`.
- Integrated persisted BFF data with `ClientsProvider`.
- Added reusable pet editing flow using the existing `PetForm`.
- Added `EditPetPage`.
- Added pet editing navigation from contextual pet actions.
- Added pet editing support from Reception search results.

### ♻️ Changed

#### Client and pet state

- Replaced frontend client mock initialization with data loaded from the BFF.
- Kept `ClientsContext` as shared UI state while SQLite acts as the persistent data source.
- Added client Context synchronization after persisted client updates.
- Added pet Context synchronization after persisted pet updates.
- Moved client and pet ID generation responsibility from the frontend to SQLite.
- Removed frontend-generated pet IDs from the pet creation flow.
- Aligned client and pet data contracts between the frontend and BFF.

#### Architecture

- Migrated client and pet data access from in-memory mocks to SQLite persistence.
- Introduced Repository abstraction to isolate persistence from business and HTTP layers.
- Established the application data flow:

  `React → Service → REST API → Route → Controller → Service → Repository → SQLite`

- Kept frontend Context focused on current application/UI state rather than permanent persistence.
- Reused `PetForm` for both pet creation and editing.

### 🛠️ Fixed

- Fixed client list rendering key warning.
- Fixed pet creation for existing clients.
- Fixed pet lookup using persistent pet IDs.
- Fixed client updates so changes persist after browser refresh.
- Fixed pet updates so changes persist after browser refresh.
- Fixed client and pet Context synchronization so persisted changes appear immediately without requiring a refresh.
- Fixed `GET /clients` responses to include each client's pets.
- Fixed Reception search errors caused by missing pet collections.
- Fixed CORS errors between the frontend on port `3002` and BFF on port `3000`.

### ⚠️ Known limitations

- Appointments are still managed in frontend state and are not yet persisted.
- Clinical consultations and clinical history are not yet persisted in SQLite.
- Database schema creation is currently handled directly during BFF initialization; a migration strategy has not yet been introduced.
